# ScriptBridge 网站下一步改进清单

> 用法：每完成一项，把 `[ ]` 改成 `[x]`，并在“结果”里写一句实际发生了什么。

## 当前判断

现在网站不缺一个巨大功能。最重要的是把已经来的 16 个候补用户变成可以联系、可以访谈、可以验证需求的线索。

所以优先级不是继续做复杂交易系统，而是：

1. 确认线上注册、验证、重置密码真的能跑通。
2. 把候补名单后台变成能运营线索的工具。
3. 再根据真实用户反馈决定要不要继续做市场、详情、上传和授权流程。

---

## 1. 线上闭环测试

- [ ] 推送当前网站代码到 GitHub

为什么改：本地能跑不代表线上能跑。GitHub Pages 才是用户实际访问的地方。

怎么改：只提交网站相关文件，不提交无关文档和旧素材改动。

用什么改：GitHub Desktop 或终端 Git。

完成标准：GitHub Pages 部署完成，`https://scriptbridge.cn` 能看到最新页面。

结果：

- [ ] 测试新账号注册和邮箱验证

为什么改：如果验证邮件跳错地址，用户注册后就卡死。

怎么改：用一个测试邮箱注册，点击验证邮件，确认回到 `https://scriptbridge.cn/login.html?verified=1`。

用什么改：Supabase Auth + 线上网页。

完成标准：邮箱验证后能正常登录。

结果：

- [ ] 测试忘记密码和重置密码

为什么改：登录系统一旦有用户，就必须能自助找回密码。

怎么改：在登录页点忘记密码，收邮件，确认跳到 `reset-password.html` 后能设置新密码。

用什么改：Supabase Auth + 线上网页。

完成标准：新密码保存成功，并能用新密码登录。

结果：

## 2. 候补名单后台升级

- [ ] 后台增加“显示完整邮箱 / 隐藏邮箱”开关

为什么改：邮箱是隐私数据，页面默认打码是对的；但你作为管理员需要能查看完整邮箱来联系用户。

怎么改：保留默认打码，增加一个按钮切换完整显示。

用什么改：`admin-waitlist.html`。

完成标准：默认显示打码邮箱，点击按钮后显示完整邮箱，再点恢复打码。

结果：

- [ ] 每一行增加“复制邮箱”按钮

为什么改：你现在已经有 16 个线索，复制联系信息应该一键完成，不要每次导出 CSV。

怎么改：在邮箱列或操作列增加复制按钮，点击后把完整邮箱写入剪贴板。

用什么改：`admin-waitlist.html` 的表格渲染逻辑。

完成标准：点击按钮后能复制完整邮箱，并显示复制成功提示。

结果：

- [ ] 修复 CSV 导出的字段转义

为什么改：CSV 里如果出现引号、逗号、换行，表格可能错位。虽然邮箱通常没问题，但这个后台以后会加备注字段，提前修好。

怎么改：新增 `csvCell()` 工具函数，把字段里的 `"` 转成 `""`。

用什么改：`admin-waitlist.html` 的 `exportCSV()`。

完成标准：导出的 CSV 在 Numbers / Excel / Google Sheets 中列不乱。

结果：

- [ ] 移除后台直接查表 fallback，只保留 RPC

为什么改：管理员数据应该只通过 `admin_waitlist_rows()` 读取，安全边界放在 Supabase SQL 函数里，前端不要保留绕路逻辑。

怎么改：删掉 `.from('waitlist_signups').select(...)` fallback，RPC 失败就显示错误。

用什么改：`admin-waitlist.html`。

完成标准：后台只调用 `admin_waitlist_rows()`。

结果：

## 3. 候补用户运营字段

- [ ] 给候补名单增加联系状态字段

为什么改：16 个邮箱不能只停留在“有人留下邮箱”。你需要知道谁联系过、谁回复过、谁适合访谈。

怎么改：给 `waitlist_signups` 增加 `contact_status` 字段，建议状态为 `new`、`contacted`、`replied`、`not_fit`。

用什么改：Supabase SQL。

完成标准：数据库里每个候补用户都有一个联系状态。

结果：

- [ ] 增加备注字段

为什么改：用户为什么感兴趣、是不是创作者/买家、是否值得继续聊，都需要记录。

怎么改：给 `waitlist_signups` 增加 `notes` 字段。

用什么改：Supabase SQL + `admin-waitlist.html`。

完成标准：后台可以看到并编辑备注。

结果：

- [ ] 后台增加状态筛选

为什么改：以后候补用户变多，必须能快速筛选“未联系”“已回复”的人。

怎么改：增加一个下拉筛选器，根据 `contact_status` 过滤表格。

用什么改：`admin-waitlist.html`。

完成标准：能按状态筛选线索。

结果：

## 4. 公开页转化优化

- [ ] 首页候补区文案改得更具体

为什么改：现在“Join waitlist”可以用，但还不够说明用户为什么要留下邮箱。

怎么改：明确告诉用户内测能获得什么，例如优先参与剧本展示、授权流程测试、创作者访谈。

用什么改：`index.html`。

完成标准：用户能一眼看懂留下邮箱后会发生什么。

结果：

- [ ] Marketplace 空状态改成 private beta 说明

为什么改：如果没有公开剧本，用户可能误以为平台没人用。要明确这是内测阶段，不是空站。

怎么改：空状态文案改成“市场正在内测，加入候补名单获取开放通知”。

用什么改：`marketplace.html`。

完成标准：空市场不会显得失败，而是显得有阶段感。

结果：

- [ ] 首页和市场页统一候补入口

为什么改：用户从任何入口来，都应该被引导到同一个候补名单动作。

怎么改：所有 Join / Early Access 按钮都指向 `index.html#signup`。

用什么改：`index.html`、`marketplace.html`、`css/common.css`。

完成标准：公开页主要 CTA 行为一致。

结果：
