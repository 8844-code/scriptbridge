# Claude 协作工作流程 V1.0

> 最后更新：2026-05-08  
> 基于：RJ + Claude 实际协作过程的反思与优化

## ⚠️ 核心问题（需要永远记住）

1. **没有实时记录 = 信息混乱**
   - 我不能等到最后才总结
   - 每一个改动、每一个决定，都要在过程中记录
   - 否则最后连"到底发了什么"都搞不清

2. **假设 = 灾难**
   - 不能凭记忆或猜测说"应该是这样"
   - 每一个事实都要确认，不要问重复问题
   - 错了就承认，马上改

3. **流程 ≠ 选项列表**
   - RJ 要的不是"给你3个选项，你选一个"
   - RJ 要的是"明确的下一步是什么"
   - 流程是为了避免重复、避免混乱、避免浪费时间

---

## 📋 RJ 提出的改进要求（2026-05-08）

### 1. 实时记录
- ❌ **错**：等到最后才问"到底发了什么"
- ✅ **对**：在过程中就记录每一个改动
  - 文案从A改成B时，**立即记录**这个改动
  - 配图从6张改成9张时，**立即记录**这个决定
  - 标签从8个优化到10个时，**立即记录**理由

### 2. 不要问重复问题
- ❌ **错**："这篇发没发？""私信回复了吗？"
  - 用户已经说过的事，不要再问
  - 你应该有记录，直接查记录
- ✅ **对**：保持单一真实来源（one source of truth）
  - 每篇发布的文案都要有对应的记录文件
  - 状态清晰：已发 / 待发 / 草稿

### 3. 明确说出改动理由
- ❌ **错**：直接给出改后的版本
- ✅ **对**：**改了什么 + 为什么改**
  ```
  改动：将"免费试读20-30%"改为"双方权益保障（完善中）"
  理由：试读功能还未开发，不应过度承诺；权益保障是核心竞争力
  ```

### 4. 一条条确认，不要假设
- ❌ **错**：假设"应该是这样"，然后创建了一堆文档
- ✅ **对**：
  1. 问清楚一条
  2. 确认无误
  3. 记录下来
  4. 再问下一条

### 5. 流程 = 清晰的下一步
- ❌ **错**：给3个方案，让RJ选
- ✅ **对**：
  ```
  现在的状态：已发2篇，私信3个用户
  下一步：整理私信反馈 → 分析哪类内容最有效 → 规划第3篇主题
  ```

## 🔄 标准工作流程（下次用这个）

### Phase 1: 准备阶段 ⏰ 1-2分钟

**RJ 提供：**
- [ ] 文案主题或核心观点（2-3句话）
- [ ] 配图资源或设计方向（几张图？什么风格？）
- [ ] 发布平台 & 约束条件（小红书、B站、公众号？）
- [ ] 参考资料（之前的文案、产品文档等）

**Claude 确认：**
- 我有了所有需要的信息吗？还缺什么？
- 直接列出清单，不要猜

---

### Phase 2: 初稿阶段 ⏰ 5-10分钟

**Claude 的工作：**
1. 写初稿
2. 标注改动理由（如果有融合之前的内容）
3. **立即保存到草稿文件**
   - 文件名格式：`草稿-{日期}-{标题}.md`
   - 包含：文案 + 配图说明 + 标签 + 版本号

**不做的事：**
- ❌ 不给多个选项（只给最优方案）
- ❌ 不假设"应该是什么意思"
- ❌ 不在没有确认前就创建发布文件

---

### Phase 3: 反馈阶段 ⏰ 根据需要

**RJ 反馈：**
- 提出具体改进点：
  ```
  改进1：第2段的语气太官方，改得更真诚一点
  改进2：加上这个emoji会不会太多？
  改进3：这个标签热度能再高一点吗？
  ```

**Claude 的工作：**
1. 立即调整
2. **明确说出改了什么**
   ```
   ✏️ 改动 1：第2段语气调整，加入个人经历细节
   改前：...
   改后：...
   理由：更有说服力，容易引发共鸣
   ```
3. 更新草稿文件版本号
4. 询问："还有其他改进吗？"

**不做的事：**
- ❌ 不创建3个不同版本让RJ选
- ❌ 不说"这样改对不对？"（直接改，然后展示）
- ❌ 不遗漏任何改动

---

### Phase 4: 确认阶段 ⏰ 1分钟

**确认清单：**
- [ ] 文案内容无误
- [ ] 配图数量和顺序对吗？
- [ ] 标签确定了吗？
- [ ] 发布时间定了吗？

**RJ 说"可以发了"时：**
- Claude 创建最终发布文件
  - 文件名：`已发-{日期}-{标题}.md`
  - 包含：最终文案 + 配图列表 + 标签 + 发布时间 + 预期指标

---

### Phase 5: 发布 & 追踪 ⏰ 实时

**RJ 发布后立即告诉 Claude：**
```
已发布：[帖子链接或ID]
发布时间：[具体时间]
配图：[实际上传的图片数量/质量]
```

**Claude 记录：**
- 更新发布文件
- 添加发布数据区域（等待填充）
```
## 📊 发布数据

发布时间：2026-05-08 14:30
初始浏览：[待更新]
初始反馈：[待更新]
```

---

### Phase 6: 迭代 & 学习 ⏰ 每周总结

**每周或每3条帖子后：**
1. 整理所有已发文案的数据
2. 分析：哪类内容效果最好？
3. 记录学到的规律
4. 调整下周策略

## 📁 文件管理标准

### 文件名格式
```
草稿：      draft-{日期}-{标题}-v{版本号}.md
已确认：    confirmed-{日期}-{标题}.md
已发布：    published-{日期}-{标题}.md
```

### 文件内容标准
```markdown
# {标题}

## 📋 基本信息
- 创建日期：
- 最后更新：
- 状态：[草稿/确认/已发]
- 版本号：

## 📝 文案
[完整文案]

## 📸 配图
- 图1：[说明]
- 图2：[说明]
...

## 🏷️ 标签
[10个标签]

## 📊 发布数据
[发布后填充]
```
